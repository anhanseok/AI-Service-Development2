## Question

초대 기반 캘린더 공유 기능을 구현한다.

체크리스트:
- API Route: 이메일로 초대 (가입된 사용자인지 확인, 아니면 에러 응답)
- 멤버로 등록되면 해당 사용자의 캘린더 목록에 노출
- 멤버 목록 조회 및 표시 UI (02번 프로토타입 반영)

## Answer

초대 기반 공유 구현 완료.

API Routes:
- `GET /api/calendars/:id/members` — 멤버 목록 (소유자 표시 포함), 멤버만 접근 가능
- `POST /api/calendars/:id/members` — 이메일로 초대. `public.User`에서 이메일 조회 → 없으면 404 "가입된 사용자만 초대할 수 있습니다.", 이미 멤버면 409, 성공 시 201

화면: 캘린더 헤더의 "멤버 초대 (N)" 버튼 → 모달(이메일 입력 + 결과 메시지 + 현재 멤버 목록). 02번 프로토타입 그대로.

검증 (테스트 계정 3명: owner / friend / stranger):
- 미가입 이메일 초대 → 404 거부
- 가입자 초대 → 201, friend의 캘린더 목록에 즉시 노출
- 중복 초대 → 409 거부
- friend가 공유 캘린더의 일정 조회·추가 가능 (01번 결정대로 멤버 전원 동일 권한)
- **stranger가 자기 자신을 멤버로 추가 시도 → 403**, 멤버 목록 조회도 403

설계 메모: 초대는 "승인 대기" 상태 없이 즉시 멤버로 추가된다(01번에서 role/초대 상태를 두지 않기로 확정한 결과). 멤버 제거 기능은 MVP 범위 밖이라 만들지 않음 — 필요해지면 별도 티켓.

이메일 조회는 소문자로 정규화해서 매칭한다(Supabase가 이메일을 소문자로 저장).
