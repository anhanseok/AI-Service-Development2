# Quickstart: 할 일 관리 기능 검증

**Date**: 2026-09-16 | **Contract**: [contracts/tasks-api.md](./contracts/tasks-api.md)

구현이 끝난 뒤 이 순서대로 실행하면 스펙의 요구사항이 실제로 동작하는지 확인할 수 있다.
자동화 테스트 프레임워크는 도입하지 않았다(R-007). 아래 시나리오가 검증 수단이다.

## 사전 준비

```bash
npm install
npx prisma migrate dev --name init   # dev.db 파일이 생성된다
npm run dev                          # http://localhost:3000
```

`.env`에 `DATABASE_URL="file:./dev.db"` 한 줄이 있어야 한다.

## A. 완료 조건 (헌법 "개발 워크플로")

```bash
npm run lint
npm run build
```

둘 다 통과해야 작업을 완료로 간주한다. `any` 사용이 있으면 이 단계에서 걸린다(원칙 III).

## B. API 검증 (curl)

PowerShell에서는 `curl`이 `Invoke-WebRequest` 별칭이므로 `curl.exe`로 호출한다.

| # | 시나리오 | 명령 | 기대 결과 | 요구사항 |
|---|----------|------|-----------|----------|
| B1 | 빈 목록 조회 | `curl.exe http://localhost:3000/api/tasks` | `{"ok":true,"data":[]}` | FR-012 |
| B2 | 할 일 추가 | `curl.exe -X POST http://localhost:3000/api/tasks -H "Content-Type: application/json" -d "{\"title\":\"우유 사기\"}"` | 201, `completed:false` | FR-001, FR-005 |
| B3 | 빈 제목 거부 | 위와 같되 `-d "{\"title\":\"   \"}"` | 400 `VALIDATION_ERROR`, **JSON 본문** | FR-002, 원칙 II |
| B4 | 101자 제목 거부 | `title`에 101자 입력 | 400, 100자 안내 | FR-004 |
| B5 | 앞뒤 공백 제거 | `-d "{\"title\":\"  책 읽기  \"}"` | 저장된 `title`이 `"책 읽기"` | FR-003 |
| B6 | 제목 중복 허용 | B2를 똑같이 한 번 더 | 201, 서로 다른 `id` 2건 | FR-015 |
| B7 | 완료 토글 | `curl.exe -X PATCH http://localhost:3000/api/tasks/1 -H "Content-Type: application/json" -d "{\"completed\":true}"` | 200, `completed:true` | FR-008 |
| B8 | 같은 값 재전송 | B7을 한 번 더 | 200, 결과 동일 (멱등) | R-005 |
| B9 | 정렬 확인 | `curl.exe http://localhost:3000/api/tasks` | 최근 추가분이 배열 앞 | FR-007 |
| B10 | 삭제 | `curl.exe -X DELETE http://localhost:3000/api/tasks/1` | 200 | FR-009 |
| B11 | 없는 항목 조작 | B10을 한 번 더 | 404 `NOT_FOUND`, JSON 본문 | FR-014 |
| B12 | 잘못된 id | `curl.exe http://localhost:3000/api/tasks/abc -X DELETE` | 400 `VALIDATION_ERROR` | V-05 |

**B3·B11이 이 검증의 핵심이다.** 실패 응답까지 JSON이어야 헌법 원칙 II를 만족한다.
HTML 에러 페이지가 돌아오면 구현이 잘못된 것이다.

## C. 화면 검증 (브라우저)

`http://localhost:3000` 접속 후 순서대로 확인한다.

| # | 동작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| C1 | 할 일이 없는 상태로 접속 | 두 구역 모두 비어 있다는 안내가 보인다 | FR-012 |
| C2 | 제목 입력 후 추가 | 미완료 구역 **맨 위**에 나타난다 | FR-001, FR-006, FR-007 |
| C3 | 아무것도 입력하지 않고 추가 | 추가되지 않고 제목이 필요하다는 안내 | FR-002 |
| C4 | 완료 표시를 켠다 | 미완료 구역에서 사라지고 완료 구역에 나타난다 | FR-008, FR-006 |
| C5 | 완료 표시를 끈다 | 다시 미완료 구역으로 돌아온다 | FR-008 |
| C6 | 삭제 버튼 → 취소 | 할 일이 그대로 남는다 | FR-010 |
| C7 | 삭제 버튼 → 확인 | 목록에서 사라진다 | FR-009, FR-010 |
| C8 | 브라우저를 닫았다 다시 연다 | 이전 내용이 그대로 있다 | FR-011, SC-003 |

## D. 다중 탭 검증 (자동 갱신)

| # | 동작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| D1 | 같은 주소를 탭 2개에 연다. 탭1에서 할 일을 추가한다 | 탭2에서 아무 조작 없이 **5초 이내** 나타난다 | FR-016, SC-006 |
| D2 | 탭1에서 할 일을 삭제한다. 탭2가 갱신되기 전에 탭2에서 그 항목의 완료 표시를 누른다 | 안내가 뜨고 탭2 목록이 최신 상태로 맞춰진다 | FR-013, FR-014 |
| D3 | 탭2를 다른 탭 뒤로 숨긴 뒤 탭1에서 추가하고, 탭2로 돌아온다 | 돌아온 직후 목록이 최신 상태다 | R-006 |

D2가 폴링만으로는 덮이지 않는 경로다. 실패 처리가 실제로 동작하는지 여기서 드러난다.

## E. 데이터가 실제로 파일에 있는지 확인

```bash
npx prisma studio
```

브라우저에 열리는 표에서 `Task` 테이블을 확인한다. C2에서 추가한 제목이 행으로 보이면
데이터가 메모리가 아니라 `dev.db` 파일에 저장된 것이다.

`dev.db` 파일 자체의 용량이 할 일을 추가할 때마다 커지는 것으로도 확인할 수 있다.
