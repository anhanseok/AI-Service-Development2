# Quickstart: 중요도 기능 검증

**Date**: 2026-09-17 | **Contract**: [contracts/tasks-api-priority.md](./contracts/tasks-api-priority.md)

001의 [quickstart.md](../001-todo-management/quickstart.md) 시나리오는 **모두 그대로 통과해야 한다**
(회귀 확인). 아래는 중요도 때문에 새로 필요한 검증이다.

## 사전 준비

```bash
npx prisma migrate dev --name add_priority
npm run dev
```

마이그레이션 직후 **기존 할 일이 모두 MEDIUM으로 보이는지** 먼저 확인한다(FR-112).
데이터를 지우고 시작하면 이 항목을 검증할 수 없으므로, 기존 데이터가 있는 상태에서 실행한다.

## A. 완료 조건

```bash
npm run lint
npm run build
```

## B. API 검증

PowerShell에서는 `curl.exe`로 호출한다. 한글 제목을 인라인 `-d`로 보내면 셸 인코딩 때문에
깨질 수 있으므로, 이 절의 예시는 ASCII 제목을 쓴다.

| # | 시나리오 | 기대 결과 | 요구사항 |
|---|----------|-----------|----------|
| P1 | 마이그레이션 직후 기존 할 일 조회 | 모두 `"priority":"MEDIUM"` | FR-112 |
| P2 | `{"title":"a"}` 로 추가 (priority 생략) | `"priority":"MEDIUM"` | FR-103 |
| P3 | `{"title":"b","priority":"HIGH"}` 로 추가 | `"priority":"HIGH"` | FR-102 |
| P4 | `{"title":"c","priority":"URGENT"}` 로 추가 | 400, `중요도는 HIGH, MEDIUM, LOW 중 하나여야 합니다.` | FR-106, V-07 |
| P5 | `{"title":"d","priority":"high"}` 로 추가 | 400 (대소문자 구분) | V-07 |
| P6 | `PATCH {"priority":"LOW"}` | 200, `"priority":"LOW"`, `completed` 는 그대로 | FR-105 |
| P7 | `PATCH {"completed":true}` | 200, `completed` 만 바뀌고 `priority` 는 그대로 | R-104 |
| P8 | `PATCH {"completed":true,"priority":"HIGH"}` | 200, 둘 다 바뀜 | R-104 |
| P9 | `PATCH {}` | 400, `변경할 내용이 없습니다.` | V-08 |
| P10 | `PATCH {"priority":"LOW"}` 를 두 번 | 두 번 다 200, 결과 동일 (멱등) | — |
| P11 | 없는 id 에 `PATCH {"priority":"LOW"}` | 404 `NOT_FOUND`, JSON 본문 | FR-114 |

### B-정렬: 핵심 검증

LOW → HIGH → MEDIUM → HIGH 순서로 4건을 **이 순서대로** 추가한 뒤 `GET /api/tasks` 를 호출한다.

| # | 확인 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| S1 | 응답 배열의 `priority` 나열 | `HIGH, HIGH, MEDIUM, LOW` | FR-107 |
| S2 | 두 HIGH 의 순서 | 나중에 추가한 HIGH 가 먼저 | FR-108 |
| S3 | 같은 요청을 10번 반복 | 10번 모두 동일한 id 순서 | FR-113, SC-105 |

S2가 이 기능에서 가장 틀리기 쉬운 지점이다. 정렬이 안정적이지 않으면 같은 등급의 순서가
호출마다 달라진다.

## C. 화면 검증 (브라우저)

| # | 동작 | 기대 결과 | 요구사항 |
|---|------|-----------|----------|
| C1 | 추가 폼을 연다 | 중요도 선택이 보이고 기본값이 "보통" | FR-102, FR-103 |
| C2 | 중요도를 "높음"으로 골라 추가 | 목록 맨 위 HIGH 묶음에 나타남 | FR-102, FR-107 |
| C3 | 추가 직후 폼을 본다 | 중요도 선택이 "보통"으로 돌아와 있음 | FR-104 |
| C4 | 목록의 각 항목을 본다 | 항목마다 현재 중요도가 보이고 세 등급이 구별됨 | FR-110 |
| C5 | LOW 항목을 HIGH 로 바꾼다 | 그 항목이 HIGH 묶음으로 이동 | FR-105, FR-107 |
| C6 | 화면을 새로 연다 | 바뀐 중요도 유지 | FR-111 |
| C7 | 완료 처리된 항목의 중요도를 바꾼다 | 완료 구역 **안에서** 자리가 바뀜. 미완료 구역으로 올라오지 않음 | FR-109 |
| C8 | 중요도 선택을 키보드만으로 조작 | 탭·방향키로 선택 가능 | R-105 |

C7이 구역과 정렬이 서로 간섭하지 않는지 보는 지점이다.
